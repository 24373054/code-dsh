## 5. Browser UI: legacy web console vs plugin browser half

The legacy `web-console` is a standalone SPA built on the `dsh-ui-kit` shell
(`apps/console`, `@trust-console/console`, `App.tsx` + `api.ts`): a three-column
console with 8 navigation panels, a right-hand detail pane, and a
"run the full demo chain" action that performs the whole write flow
(register agent + router → task → delegation → event → verify → risk →
intervention → execute → case trace → report) directly against the control
plane. It was **not** migrated; it lives in the archive.

The plugin's browser half is a set of Cordis slot contributions inside DSH,
backed by the Host route `GET /trust-platform/api/overview` (plus
`GET /trust-platform/api/health`), fenced by the `connection` service
(401/403 rejections leave the panel mounted), read-only (`GET`/`HEAD` only,
405 otherwise). Files: `src/client/index.jsx`, `overview.jsx`, `overview-data.js`,
`settings.jsx`, `toolviews.jsx`, `badge.jsx`, `format.js`, `locales.js`
(zh + en), `styles.js`; Host side: `src/ui-route.js`.

## 8. Verdict

**Backend runtime preserved — yes.** The authoritative FastAPI control plane now
runs entirely from `control-plane/` with a fresh, isolated, pinned virtual
environment. The relocated server serves an OpenAPI document that is
byte-identical to the legacy one, and both integration harnesses pass
(48/48 and 55/55) against it. Nothing in the relocated tree refers back to
`code/`, so `code/` is disposable once the owner decides to delete it.

**All agent-facing capabilities reachable — yes.** As of v0.5.0, 55 of the 56
legacy operations are reachable through the plugin client (only `GET
/v1/events/stream`, SSE, remains unrouted) and 54 endpoints (55 including the
conditional intervention execution) are covered by the 58 registered
control-plane agent tools: 9 canonical, 27 adapter and 22 full-surface tools.
G1 (`/metrics`) and G3 (21 route-only endpoints) are closed. The only remaining
product gap is UI-side: the archived legacy console offered
browsing/detail/registry panels that the plugin's browser half (overview,
settings, tool cards) does not reproduce in full (G6); the data behind those
panels is now reachable through the tools and the HTTP API.
